O problema dos "agentes autônomos de DS"

🤖

Exageram no escopo

Demos fingem que o pipeline inteiro roda sem ninguém. Na hora que a realidade bate — mudança de schema, uma coluna estranha, uma lib instável — eles quebram sem avisar direito.

📦

Saídas one-shot

Quando "funcionam", a entrega é um zip de código + gráficos. Sem PR, sem revisão, sem histórico incremental em que dê pra confiar.

🔁

Cultura de recomeçar

Cada execução começa do zero. Nada acumula. Humano não consegue continuar de onde o agente parou — nem vice-versa.

🤝

DS é colaborativo

Falta é um teammate — que trabalha em tickets individuais, respeita o seu WIP e deixa você revisar.

Cortex é um teammate,
não um agente autônomo.

1 issue = 1 run = 1 PR

Backlog compartilhado

Você e o Cortex pegam tickets do mesmo backlog de issues. Sem colisão.

Humano dá o merge

Cortex abre PRs. Você revisa e mergeia como faria pra qualquer colega.

Falhe alto

Bloqueios reais aparecem na hora. Nada de "tem certeza?" em trivialidade.

Dois breakpoints humanos

Plano (Cortex deveria mesmo fazer isso?) e pós-modelagem (métricas valem merge?). Todo o resto roda sem intervenção.

Postgres como checkpointer

Retomar após aprovação é só graph.invoke(None). Estado sobrevive a redeploy, falha parcial, restart.

Guards anti-loop

Re-entrar em modeling após aprovação é bloqueado. Review loop limitado. Sem queima infinita de tokens.

Contexto da issue no state

Número da issue que disparou o run viaja no state, pra node_report fechar ela no final.

Relatórios determinísticos

LLM escreve decisões

Classificação, narrativa, escolha de hipótese, justificativa de métrica — o que precisa de julgamento.

Repo escreve estrutura

Templates Quarto fixados em templates/*.qmd. O agente produz summary.json; o template renderiza.

Resultado: toda execução entrega o mesmo shape de HTML. Dá pra fazer diff entre relatórios de runs. Mudanças de schema ficam revisáveis no Git.
zero surpresa grep-ável reproduzível auditável

Modelo de concorrência

Seguro entre teammates: humanos e Cortex compartilham o mesmo backlog sem pisar um no outro.

🏷️

Claim via label

Adicionar cortex:in-progress é o lock. Label ausente = claimável. Atômico o bastante pra eventual consistency do GitHub.

⏱️

Lease com timestamp ISO

Comentário na issue com lease-until: <ts>. Um sweeper futuro recicla leases órfãos.

🏁

Detecção de race

Relê a issue logo antes de escrever. Se alguém claimou na janela, volta com status: skipped.

🧹

Release no fim

Fim do run: remove label + fecha issue. Se push falhou: só release (deixa aberta pra retry).

Takeaways

Colaborador, não autônomo. O humano sempre é dono do merge.
Estrutura no repo, decisões no LLM. Templates fixos; prompts mudam.
Intenção explícita > defaults espertos. auto_create_repo é pedido, nunca inferido.
Falhe alto. Não peça aprovação em trivialidade.
